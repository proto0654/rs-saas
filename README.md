# Локаль · MVP
Целевая папка Windows: `E:\vue-projects\rs-saas`.
Это демонстрационное Nuxt-приложение и исходные материалы для MVP.

1. Распаковать содержимое этой папки в корень проекта. Существующие файлы не заменять без проверки.
2. Открыть проект в Cursor. Прочитать `docs/PRODUCT.md`, `docs/DESIGN.md` и изображения `references/`.
3. Выполнять промпты из `prompts/` по порядку. Начать с `01-build.md`.
4. Сид: `demo/seed.json`. Чистые функции: `demo/domain.mjs`. Тесты: `demo/domain.test.mjs`.
5. Запустить тесты: `npm test`.

Все имена, отзывы, цены, координаты и брони — вымышленные демонстрационные данные, не реальные предложения. Города реальные; точки приблизительные. Демо-дата: 2027-06-12 (Europe/Moscow). Ни платежи, ни проверки личности не выполняются.

## Состав
- references/01-guest-mobile.png — основа гостевого UI.
- references/02-host-mobile.png — основа кабинета хозяина.
- references/03-dark-direction.png — общий характер, вторичный референс.
- docs/ — продукт, дизайн, модель и сценарии проверки.
- prompts/ — последовательные задания для Cursor.
- demo/ — связанный JSON, функции и тесты Vitest.
- public/demo/ — сгенерированные изображения вымышленных объектов и исходные SVG-заглушки.

Зафиксированный стек: Nuxt 4 + Vue 3 + TypeScript + Tailwind CSS 4 + daisyUI 5 (выборочно) + Pinia через @pinia/nuxt + Vitest + Vue Test Utils + @nuxt/test-utils. Nuxt управляет маршрутизацией и сборкой; отдельные Vite entrypoint и createRouter не нужны. Установленные версии зафиксированы в package-lock.json.

Прочитать также docs/ARCHITECTURE.md и docs/STACK.md. В templates/ лежат стартовые примеры nuxt.config.ts, CSS-темы и vitest.config.ts: это заготовки для интеграции Cursor, не отдельное готовое приложение. Для реального SSR использовать серверный запуск Nuxt, не статический generate. Backend пока заменяет DemoRepository.

Ревизия 2: заменена архитектура Vue/Vite на Nuxt, добавлены границы SSR, локальная гидратация демо-состояния и тема daisyUI. Изображения и сид сохранены.

## Запуск MVP

Нужен Node.js 22. Выполните `npm install`, затем `npm run dev` и откройте адрес, указанный Nuxt. Проверки: `npm test`, `npm run typecheck`, `npm run build`; production-сервер: `npm run preview`.

В шапке переключаются гость, хозяин и браузерный просмотр Telegram Mini App. В кабинете хозяина доступны объекты, шахматка, заявки, журнал и симуляция личного бота. Данные сохраняются в localStorage конкретного браузера; другой браузер и серверная выдача видят исходный сид. Сброс находится в профиле и не удаляет данные других приложений. Изображения объектов сгенерированы и не представляют реальные предложения.

Для настоящего общего Telegram-бота на grammY задайте переменные `BOT_TOKEN` и `MINI_APP_URL` (публичный HTTPS-адрес приложения с путём `/tg`) в окружении или в локальном `.env` и запустите `npm run bot`. Локальный запуск бота откажется работать, если у токена уже настроен webhook: для polling используйте отдельного бота. Сам сайт для тестирования не требует токена и работает без Telegram SDK. Персональный бот в кабинете — симуляция: его демо-токен не является токеном Telegram и ничего не подключает. Реальные платежи, серверная авторизация, общая база и настоящий аудит отсутствуют; журнал демонстрационный и хранится в браузере.

Карта использует Яндекс Карты. Для интерактивных меток задайте `NUXT_PUBLIC_YANDEX_MAPS_KEY` в окружении Nuxt и перезапустите сервер; без ключа показывается виджет карты без меток объектов. Ключ JavaScript API публичный и должен быть ограничен разрешёнными доменами в кабинете Яндекса.

Каталог: 60 вымышленных объектов в 27 городах Крыма, Кубани и юга России, включая обычные квартиры, хостелы и 12 вариантов долгосрока. После обновления используйте «Сбросить демо» в профиле, чтобы загрузить все примеры; сохранённые изменения автоматически не заменяются. [Сценарии показа](docs/DEMO.md).
