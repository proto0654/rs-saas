# Зафиксированное направление
Графитовый почти чёрный фон, лаймовый акцент, тёплый белый текст, крупная плотная типографика, сдержанные реалистичные фотографии жилья Крыма, Кубани и юга России. Обычные интерьеры, естественный свет, простая мебель и нейтральные цвета; без открыточных панорам, чрезмерной насыщенности и постановочного курортного декора. Название продукта — «Локаль». Надпись «место» в исходных концептах — прежнее временное имя. Приоритет — два мобильных референса. Не копировать рамки телефонов, системные часы, островок и Telegram chrome внутрь приложения.

Предлагаемые стартовые токены (приближение по растровым макетам, не точный экспорт): background #0C1210, surface #18201C, elevated #222B25, text #F5F4EB, muted #A8B1A4, accent #D0F35B, border #3A443D. Шрифт Manrope или системный sans; заголовки 30–36/1.1, основной текст 15–16/1.5. Радиусы 12–20, кнопка 48–52px, зоны касания минимум 44px. Иконки единообразные контурные. Лайм — выбор и основные действия; статусы дополнить словами, не кодировать только цветом.

Mobile 360–430: поиск → карта/список, нижняя карточка выбранного жилья, нижняя навигация. Отдельный экран объекта, фото, характеристики, даты, цена и sticky CTA. Направление, даты/гости и все фильтры раскрываются по месту: одновременно открыта одна панель. Поля редактируют черновик, «Показать N вариантов» применяет его; закрытие и Escape отменяют изменения. Быстрые кнопки применяются сразу. На телефоне действие применения закреплено над нижней навигацией; число результатов остаётся видимым. Даты в карточке жилья раскрываются внутри блока бронирования. Хозяин: список объектов с вкладками типов → объект с вкладками «Номера / Календарь / Настройки». Для квартиры вкладка «Номера» отсутствует. Календарь допускает горизонтальный скролл, страница целиком — нет.

Desktop от 1024: результаты слева, карта справа; кабинет хозяина с боковой навигацией и широкой календарной матрицей. Все роли имеют отдельные маршруты и layout. Гостевой календарь выбора дат не смешивать с хозяйской матрицей.

Состояния: default, hover, focus-visible, active, disabled, pending; skeleton, empty, error+retry. prefers-reduced-motion, контраст, aria-label и управление клавиатурой. Safe areas через env(); Telegram viewport adapter при наличии SDK, web fallback без SDK. Telegram BackButton только через adapter. Тёмная тема основная, светлая тема Telegram не должна ломать читаемость. Платформенные API не обязательны для демо.

Карта: Яндекс Карты с метками объектов при наличии API-ключа. Близкие метки объединяются в группу, из которой можно выбрать конкретный объект. Без ключа показывается виджет без меток; список остаётся доступным. Счётчик ограничений соответствует числу удаляемых меток цены, типа, удобств и видео; направление и параметры поездки показаны отдельно. При применении панель закрывается, выдача или карта подводится в видимую область; при ошибке фокус переходит на поле. Открытие цены переводит фокус на цену. Движение учитывает prefers-reduced-motion; редактирование отдельных полей не прокручивает страницу. Возврат из объекта использует сохранённую позицию истории Nuxt и выбранную метку из store. Асинхронный MestoApp отображает приватное demo-состояние только после собственного mount: глобальный app:mounted может наступить раньше завершения гидратации экрана.

Шахматка показывает брони полосами на даты проживания и открывает подробности по нажатию; закрытые периоды обозначены штриховкой. Объекты с несколькими номерами или местами свёрнуты по умолчанию: по каждому дню показано число занятых или закрытых единиц из общего числа, строки единиц раскрываются нажатием на объект. На телефоне подробности открываются поверх экрана, а названия объектов закреплены при горизонтальной прокрутке. Даты остаются доступны для выбора блокировки.

## Реализация
Главная страница начинает с интро: название с картой и плитки со случайными фотографиями опубликованных объектов из разных регионов. Плитки собираются и расходятся при прокрутке. Название сохраняет непрозрачность и после ухода плиток прокручивается вверх; поиск расположен под ним в общем потоке. Скрытые элементы поиска недоступны для фокуса. Прямая ссылка `/search` открывает поиск без интро; при уменьшении движения сразу доступен поиск.

Геометрия интро: 3 колонки × 4 строки, ширина до 720 px с полями 28 px и gap 28 px, квадратные плитки без скругления. Масштаб 1→2,05 применяется ко всей сетке. Боковые колонки расходятся горизонтально, центральная — вертикально; задержка строк 0,06, перекрытие входа и масштаба 0,6, сглаживание прокрутки 80 мс. Расстояние прокрутки — три высоты экрана; мобильные размеры рассчитываются по той же геометрии. Контрольные координаты референса проверяются в `tests/unit/intro-motion.test.ts`.

Tailwind 4 + выборочный daisyUI 5 с одной custom theme mesto из templates/main.css. Примитивы оборачивать своими компонентами UiButton/UiInput, чтобы классы и темы оставались централизованными. Modal/sheet должен сам обеспечивать focus trap, Escape и возврат фокуса; CSS daisyUI не заменяет поведение Vue-компонента.


## Проверка соответствия концептам

После изменений экранов и перед завершением этапа сравнивать реальные скриншоты с `references/01-guest-mobile.png` и `references/02-host-mobile.png`: мобильные ширины 390–430 px, затем desktop. Проверять плотность заголовков, пропорции фотографий и карточек, отступы, видимость нижней навигации и закреплённых действий. Системные рамки и Telegram chrome из концептов не переносить. Дополнительные инструменты демо (переключатель контекста, личный бот, журнал) должны сохранять доступность основных экранов.
