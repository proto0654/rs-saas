# Presentation walkthrough

All listings, people, bookings, prices and images are fictional. Use the profile action “Сбросить демо” to load the complete showcase catalog. Reset removes current demo edits and migration backups; it leaves other applications' browser storage intact.

## Catalog coverage

Guest search keeps one full-viewport map behind a floating search/results panel: a bottom panel on mobile and a left sidebar on desktop. The panel handle and Map/List buttons collapse or expand results; filters expand the panel while editing. Selecting a marker collapses results and opens its preview card. Map fitting reserves the measured panel footprint, navigation and preview space. Manual panning is retained when panels resize; “Показать все объекты” explicitly fits results again. Zoom uses app controls on the map edge instead of the default Yandex zoom UI. Changing search results fits the new set.

On the landing page the same map stays mounted throughout the intro. It starts grayscale and under a stronger dark veil, inert, then color and the search controls fade in together (~500ms). The shell header stays fixed above the intro: line-only during the cover, with backdrop blur once the full map and search UI are revealed; the bottom nav stays hidden until then. Reaching the end of the intro scroll unlocks search immediately (including a small mobile chrome tolerance); the scroll runway never intercepts clicks. Reduced motion opens search directly. Clearing restrictions is also available from a round reset control beside “Все фильтры”, without opening the filter panel. The keyless Yandex iframe uses a calculated initial camera to reserve panel space and fit results and displays the current listing coordinates as markers. Marker selection, prices and the fit-all action require a valid API key; open listing details from the results list in the fallback. The iframe cannot expose its manually changed camera to the app, so changes to search, selection or panel geometry reload its calculated view.

The seed contains 63 properties in 27 cities across Crimea, Kuban and southern Russia: 42 apartments (12 monthly rentals), 9 hostels, 9 hotels and 3 houses. There are 115 physical units, 47 bookings, two saved favorites and one maintenance block. The first owner has 21 properties, including the original draft studio. City coordinates are approximate and are not navigation advice. Images repeat across fictional listings. The “Элитное жильё” quick filter selects three premium short-term properties and combines with the other search restrictions. Older saved catalogs automatically receive the three premium examples when their IDs are available; existing listings, bookings, favorites and filters are preserved.

New searches start without a budget, sea view, city, region, property type or video restriction. Dates, guest count and rental mode remain the basic search parameters. Previously saved custom filters and explicit URL filters are retained. City entry pages apply their city; explicit filters can return no matches in inland cities.

Destination, dates/guests and restrictions open as inline panels, one at a time. Edits remain a draft until “Показать N вариантов”; closing or Escape discards them. The action previews the matching count while the list, map and URL retain the applied search. Quick filters apply immediately. Clearing restrictions preserves the destination, dates, guests and rental mode. Applied restriction chips can be removed individually.

“Заезд сегодня” toggles the demo-today → tomorrow interval and restores the previous interval when turned off. It is absent from monthly mode and is not duplicated in the expanded panel. The previous interval and per-mode preferences survive client navigation, but are not persisted across reloads; without a previous interval, turning the shortcut off restores the seed search dates. Switching modes restores that mode’s earlier preferences during the client session; on first entry, it clears the budget and retains only amenities present in the target mode. Property type and video preference are retained. Amenity choices omit absent and universal attributes unless already selected. The search budget also limits units offered on a property page. If a saved catalog contains no published monthly listings, the search links to the profile reset and explains that reset removes current demo edits. The interactive map initially has no selected property and fits all results. Nearby markers form a group; select the group and then an object, or select an individual marker. Close the card with its close button or a click on the map background. The two original showcase properties include photo galleries; room thumbnails are illustrative.

## Storage upgrade and rollback

Schema v2 adds the expanded presentation data and optional monthly rental fields. Valid v1 browser state is upgraded in memory without replacing personal demo edits or adding conflicting sample reservations. Before the first v1 upgrade, the exact original JSON is copied once to `rs-saas-demo:v1-backup`; the main key is saved only on an explicit mutation. Reset is required to replace old examples with the new complete seed.

For rollback to a v1 application, restore the exact backup JSON to `rs-saas-demo` before loading that application. Keep an exported copy before resetting. [Migration helpers](../shared/domain/migrations.ts) support version rollback for states without monthly rentals; a v2 state containing monthly units requires the original backup because v1 cannot represent monthly prices. No production database migration is involved.

The optional premium property and search fields do not change the storage schema. On restore, catalog version 1 adds missing premium listings and their units in memory, skipping IDs that conflict with saved properties or units; existing entries are never overwritten. Before this upgrade, the original JSON is copied once to `rs-saas-demo:catalog-backup`. The main key is written on the next explicit mutation; the catalog version prevents later restores from re-adding deliberately removed entries. Restore the backup JSON to `rs-saas-demo` before loading the previous application to roll back. Previous versions ignore the optional fields, and a saved premium filter has no effect after rollback.

The historical June 12–16 / two guests / 6,000 ₽ / sea-view default is normalized in memory to unrestricted search only when the saved filters exactly match that preset. Custom filters, bookings and inventory stay intact. Before normalization, v2 state is backed up once to `rs-saas-demo:defaults-backup` (v1 uses its existing backup). Restore its exact JSON to the main key and the previous app version to roll back. Reset clears the project backups. Asset replacements keep existing image URLs, so saved listings also receive the new photographs; Git contains the previous assets for rollback.

## Verification boundaries

The app uses browser-local demo data. Another browser starts from the seed. The shared grammY bot has isolated command tests; a real conversation requires a dedicated token if the configured bot already has a webhook. Yandex Maps prefers JavaScript API 3.0 when the key accepts it (theme follows the app). If 3.0 is rejected or packages fail, the map falls back to API 2.1 with the same interactive markers and clusters. Only when both API loads fail does the keyless iframe appear; it keeps Yandex’s standard look and shows listing pins without in-app price selection.

## Image direction and provenance

The raster assets were generated with the built-in imagegen tool and inspected. They illustrate fictional listings, not real accommodation; photographs repeat across some properties. The direction is believable listing photography with natural light, practical furnishings and a mix of ordinary and premium accommodation, avoiding both run-down interiors and elaborate postcard staging. Existing image paths are retained so saved listings receive replacements. Premium examples use [coastal apartment](../public/demo/premium-coast.png), [house](../public/demo/premium-house.png), and [city apartment](../public/demo/premium-city.png) images.

## Preview publication

Public URLs: [web preview](https://app.weblaba.ru), [Telegram Mini App](https://app.weblaba.ru/tg). The menu button of [the shared demo bot](https://t.me/UBK_Real_Estate_bot) opens the Mini App; its existing webhook runtime is managed separately from this static publication.

The shared REG.RU host serves Apache files and has Node 10, so this demo uses `npm run generate` built locally with Node 22. Public property and city routes are prerendered; private and Telegram routes use the client application with the Apache fallback to `200.html`. Apache can append a trailing slash when a prerendered directory is opened; platform routing normalizes it before matching screens. There is no server API in the preview. The SSR build remains available with `npm run build` on a Node 22 host.

Static HTML reflects the build-time seed; query filters and saved state are applied in the browser. Unknown routes use the client 404 screen and may have HTTP status 200 through the fallback. Apache responses set `X-Robots-Tag: noindex, nofollow`; HTML, JSON and PNG files use `Cache-Control: no-cache` where the included header rules apply.

Run tests, typecheck and generation before upload. Inspect `.output/public` for the expected routes and ensure no bot token or `.env` is included. The public Yandex JavaScript key is intentionally included at build time and must allow the preview domain. Upload only `.output/public`, with `.htaccess`, to the dedicated preview directory `/var/www/u1396397/data/www/app.weblaba.ru` on `server199.hosting.reg.ru` as `u1396397`, using the local `weblaba_deploy` SSH key. Never publish the project root or overwrite `weblaba.ru`.

Before replacing an existing preview, retain its complete directory in a sibling release backup. Record the source commit, whether the tree had changes, and the uploaded archive SHA-256 outside the public directory. To roll back, move the failed preview aside and restore that directory. Browser-local demo data remains independent of deployed files. Verify HTTPS, `/tg/search`, a property page, a private calendar route, images and the Yandex map after publication. Bot credentials stay outside the public directory; updating its menu URL does not require changing an existing webhook.
