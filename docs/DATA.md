# Модель
users → properties(ownerId) → units(propertyId) → bookings(unitId,guestId), blocks(unitId).
Property — объект размещения. Unit — физическая бронируемая единица. Статус публикации живёт на Property, доступность вычисляется по Unit и интервалу, а не хранится как поле «свободен».
Booking сохраняет снимок ночного или месячного тарифа и уборки: изменение будущего тарифа не меняет существующую бронь. Адресов, телефонов и реальных персональных данных нет.

У Unit может быть необязательное демонстрационное изображение `image`; изображения объекта перечислены в `Property.images`. Для старых сохранённых примеров «Терраса над Ялтой» и «Кипарис» интерфейс дополняет исходную фотографию фотографиями из сида, если пользователь не менял её. Фото номеров Кипариса иллюстративные. Поле необязательно: сохранённые данные версии 2 остаются совместимы, миграция схемы не требуется; предыдущая версия проигнорирует дополнительное поле.

Сид: 2 хозяина, 2 гостя, 63 объекта в 27 городах, 115 единиц размещения, 47 броней, 1 ремонт. У host1 21 объект, включая исходные квартиру, мини-отель и черновик студии. У Кипариса 8 номеров; на демо-день 5 заняты бронями, один закрыт ремонтом, два свободны. Для «занято сегодня» считать непустое пересечение [today,tomorrow); заезды и выезды вычислять отдельно. Подпись «занят» в UI не заменяет статус брони.

Карта использует location.lat/lon; карта, список и карточка объекта всегда ссылаются на одинаковый propertyId. Фильтры проверяют вместимость выбранной unit. Amenities относятся к property в этой упрощённой модели. Редактирование хозяином и бронирование гостем проходят через один repository и единую проверку конфликтов.

Общая модель и расчёты находятся в `shared/types/demo.ts` и `shared/domain/booking.ts`. Исходный `demo/domain.mjs` экспортирует эту же реализацию. Восстановление из localStorage проверяет поля, уникальность ID и ссылки между пользователями, объектами, единицами, бронями и блокировками. При повреждённых данных используется сид; запись не перезаписывается до следующего явного изменения.

Изменение вместимости единицы не меняет исторические брони и их снимки стоимости. Уменьшить вместимость ниже числа гостей в действующей блокирующей брони нельзя; завершённые и отменённые брони этому не препятствуют. Вместимость отдельного койко-места в хостеле равна одному гостю.

География и региональные группы заданы в `shared/locations.ts`. У долгосрочной единицы `baseNightly=0`, ставка хранится в `baseMonthly`; у брони сохраняется `monthlySnapshot`. Сид и механизм обновления описаны в [сценариях показа](DEMO.md).

Признак `premium` необязателен для объектов и фильтров; он выделяет элитные предложения в поиске. Старые сохранённые каталоги остаются совместимыми, новые примеры автоматически добавляются в сохранённый каталог без перезаписи существующих данных; при совпадении идентификаторов конфликтующий пример пропускается.
